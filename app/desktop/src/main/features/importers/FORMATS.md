# Formats d'import

Description des fichiers lus par les importeurs de ce dossier. C'est le seul endroit du dépôt où les autres navigateurs sont nommés.

## Import

Réglages › Import : une ligne par navigateur du système (voir index.ts), bouton « Importer » si la source est sur le disque. Le bouton ouvre une fenêtre de choix des données trouvées, toutes cochées : espaces (Arc), favoris, mots de passe, extensions, historique. Ni onglets ouverts ni cookies. Safari n'a que ses favoris : pas de choix, l'import part directement. Actions de la barre de commande `import:arc` « Importer depuis Arc », `import:chrome` « Importer les favoris de Chrome », et de même `import:chromium`, `import:brave`, `import:edge`, `import:safari` : elles ouvrent Réglages › Import avec la fenêtre de choix de la source. Chaque donnée s'importe indépendamment (un échec n'arrête pas les autres) ; à la fin, une boîte de dialogue native résume chaque ligne (« 4 espaces, 132 onglets épinglés… », « 3 812 pages ajoutées à l'historique. », « 57 mots de passe importés. », « 6 extensions en cours d'installation… ») avec les échecs et leur raison probable. Code dans `src/main/importers/` (`chromium.ts` pour le profil Chromium). 2 000 onglets maximum par import. Les onglets importés sont créés déchargés, avec un favicon provisoire `https://icons.duckduckgo.com/ip3/<hôte>.ico` remplacé par le vrai au premier chargement.
Ne jamais lire les vrais fichiers de l'utilisateur pendant le développement (données personnelles) : coder d'après les formats décrits ici et tester sur des fichiers d'exemple fabriqués dans un dossier temporaire.

**Arc** — Mac : `~/Library/Application Support/Arc/StorableSidebar.json` ; Windows : `%LOCALAPPDATA%\Packages\TheBrowserCompany.Arc_*\LocalCache\Local\Arc\StorableSidebar.json` (emplacement non vérifié). Format (non documenté, à lire de façon tolérante) :

- `sidebar.containers` : tableau ; le conteneur utile est celui qui possède `spaces` et `items` (souvent l'index 1).
- `spaces` et `items` : tableaux qui alternent en général identifiant (chaîne) et objet ; accepter aussi des objets seuls. Indexer les objets par leur champ `id`.
- Espace : `id`, `title`, `containerIDs` qui alterne un libellé et un id d'item racine (`["pinned", "<id>", "unpinned", "<id>"]`), icône éventuelle dans `customInfo.iconType` (prendre la première valeur texte qui est un emoji, sinon ✨).
- Item : `id`, `parentID`, `childrenIds`, `title` (peut être nul), `data` qui contient une seule clé parmi `tab` (`savedURL`, `savedTitle`), `list` (dossier), `splitView` (vue partagée : ses enfants sont des onglets), `itemContainer` (racine d'un conteneur, à traverser), ou d'autres clés inconnues (ignorer).
- Favoris : `topAppsContainerIDs` alterne un descripteur et un id de conteneur ; les enfants de ce conteneur sont les favoris (globaux).
- Correspondance : chaque espace Arc → un nouvel espace (nom, emoji, teintes successives de la palette) ; arbre « pinned » → `pinned` avec dossiers et vues partagées (vue partagée de plus de 3 onglets : garder les 3 premiers, les autres en onglets seuls) ; arbre « unpinned » → onglets du jour (avec `lastActive = Date.now()`) ; favoris → favoris (sans doublon d'URL). Titre d'un onglet : `title` sinon `savedTitle` sinon l'URL. Garde-fous : identifiants déjà vus (pas de cycle), profondeur 8, champ manquant = élément ignoré, jamais d'exception non rattrapée.
- Si l'état ne contient qu'un espace vide (aucun épinglé, onglet du jour, signet ni groupe), le remplacer par les espaces importés.

**Chrome, Chromium, Brave, Edge** — fichier JSON `Bookmarks` du profil `Default`. Mac : `~/Library/Application Support/` + `Google/Chrome`, `BraveSoftware/Brave-Browser`, `Microsoft Edge`. Linux : `~/.config/` (ou `$XDG_CONFIG_HOME`) + `google-chrome`, `chromium`, `BraveSoftware/Brave-Browser`, `microsoft-edge`, puis les versions Flatpak (`~/.var/app/<id>/config/…`) et Snap (`~/snap/chromium/common/chromium`). Windows : `%LOCALAPPDATA%\` + `Google\Chrome`, `BraveSoftware\Brave-Browser`, `Microsoft\Edge`, puis `User Data\Default`. Chromium n'est proposé que sous Linux. `roots.bookmark_bar`, `roots.other`, `roots.synced` ; nœuds `{ type: 'url' | 'folder', name, url, children }`. Résultat : des signets de l'espace actif (barre de signets) : le contenu de la barre de favoris et un sous-dossier « Autres favoris » s'il n'est pas vide (et « Favoris synchronisés » de même), directement dans la barre si elle était vide, sinon dans un dossier « Chrome » (ou « Brave », « Edge ») à la fin de la barre.

**Profil Chromium** (Chrome, Chromium, Brave, Edge ; Arc : `User Data/Default` à côté de `StorableSidebar.json`) — dossier `Default` du navigateur. Les bases SQLite sont copiées dans un dossier temporaire avant lecture (le navigateur ouvert les verrouille), journal `-wal` compris, lues avec `node:sqlite` en entiers longs (les dates sont en microsecondes depuis le 1er janvier 1601).

- Historique : `History`, table `urls` (`url`, `title`, `visit_count`, `last_visit_time`), sans `hidden`, seulement http(s), les 5 000 plus récentes. Fusion : une page connue cumule les visites et garde la plus récente ; on ne garde que les 5 000 pages les plus récentes au total.
- Extensions : dossiers `Extensions/<id>` (32 lettres a–p), sauf celles marquées `was_installed_by_default`, `from_webstore: false` ou désactivées (`state: 0`, ou `disable_reasons` non vide) dans `extensions.settings` de `Secure Preferences` / `Preferences` : Signet ne garde pas d'extension installée mais désactivée. Installées une à une depuis le Chrome Web Store (celles déjà présentes sont sautées), jamais épinglées.
- Mots de passe : `Login Data`, table `logins` (`origin_url`, `signon_realm`, `username_value`, `password_value`, `date_created`), sans `blacklisted_by_user` ni identifiants d'apps (`android://`). Ajoutés au trousseau de Signet ; un identifiant déjà présent (même site, même nom) est gardé tel quel. Déchiffrement selon le préfixe de `password_value` :
  - Mac `v10` : AES-128-CBC, IV de 16 espaces, clé PBKDF2-SHA1(secret, `saltysalt`, 1003 tours, 16 octets) ; secret lu dans le Trousseau par `security find-generic-password -w -s "<Navigateur> Safe Storage"` (macOS demande l'autorisation). Services : `Chrome`, `Chromium`, `Brave`, `Microsoft Edge`, `Arc` + « Safe Storage » (celui d'Arc non vérifié).
  - Linux `v10` : même AES, clé PBKDF2-SHA1(`peanuts`, `saltysalt`, 1 tour) ; `v11` : secret du trousseau GNOME par `secret-tool lookup application <app>` (`chrome`, `chromium`, `brave`, `microsoft-edge`), 1 tour. KWallet non géré.
  - Windows `v10` : AES-256-GCM (nonce 12 octets après le préfixe, étiquette des 16 derniers), clé `os_crypt.encrypted_key` de `User Data/Local State` (base64, préfixe `DPAPI`) déchiffrée par PowerShell (`ProtectedData.Unprotect`, utilisateur courant). `v20` (« app-bound », Chrome récent) : illisible hors du navigateur, compté comme échec avec le conseil d'exporter un CSV.

**Safari** (Mac seulement) — `~/Library/Safari/Bookmarks.plist`, converti avec `execFile('plutil', ['-convert', 'json', '-o', '-', chemin])`. Nœuds : `WebBookmarkType` = `WebBookmarkTypeList` (`Title`, `Children`) ou `WebBookmarkTypeLeaf` (`URLString`, `URIDictionary.title`) ; ignorer `com.apple.ReadingList` et `History`. Résultat : des signets, comme pour Chrome (dans un dossier « Safari » si la barre n'était pas vide), avec `BookmarksBar` à la racine et `BookmarksMenu` en sous-dossier « Menu des favoris ». Erreur de permission (macOS protège ce dossier) → boîte de dialogue qui explique d'accorder l'accès complet au disque à Signet (Réglages Système › Confidentialité et sécurité › Accès complet au disque ; en développement, c'est l'app « Electron »), avec un bouton qui ouvre `x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`.

# Import formats

Description of the files read by the importers in this folder. This is the only place in the repo where other browsers are named.

## Import

Settings › Import: one row per browser on the system (see index.ts), with an "Import" button if the source is on disk. The button opens a window to choose among the data found, all checked: spaces (Arc), bookmarks, passwords, extensions, history. No open tabs and no cookies. Safari only has its bookmarks: no choice, the import starts right away. Command bar actions `import:arc` "Import from Arc", `import:chrome` "Import Chrome Bookmarks", and likewise `import:chromium`, `import:brave`, `import:edge`, `import:safari`: they open Settings › Import with the choice window for that source. Each kind of data is imported on its own (one failure does not stop the others); at the end, a native dialog sums up each row ("4 spaces, 132 pinned tabs…", "3,812 pages added to the history.", "57 passwords imported.", "6 extensions being installed…") with the failures and their likely cause. Code in `src/main/features/importers/` (`chromium.ts` for the Chromium profile). 2,000 tabs at most per import. Imported tabs are created unloaded, with a temporary favicon `https://icons.duckduckgo.com/ip3/<host>.ico` replaced by the real one on first load.
Never read the user's real files during development (personal data): code from the formats described here and test on sample files built in a temporary folder.

**Arc**, Mac: `~/Library/Application Support/Arc/StorableSidebar.json`; Windows: `%LOCALAPPDATA%\Packages\TheBrowserCompany.Arc_*\LocalCache\Local\Arc\StorableSidebar.json` (location not verified). Format (undocumented, read it leniently):

- `sidebar.containers`: array; the useful container is the one that has `spaces` and `items` (often index 1).
- `spaces` and `items`: arrays that usually alternate an identifier (string) and an object; also accept objects alone. Index the objects by their `id` field.
- Space: `id`, `title`, `containerIDs` which alternates a label and a root item id (`["pinned", "<id>", "unpinned", "<id>"]`), optional icon in `customInfo.iconType` (take the first text value that is an emoji, otherwise ✨).
- Item: `id`, `parentID`, `childrenIds`, `title` (may be null), `data` which holds a single key among `tab` (`savedURL`, `savedTitle`), `list` (folder), `splitView` (split view: its children are tabs), `itemContainer` (root of a container, walk through it), or other unknown keys (ignore).
- Favorites: `topAppsContainerIDs` alternates a descriptor and a container id; the children of that container are the favorites (global).
- Mapping: each Arc space → a new space (name, emoji, successive tints from the palette); "pinned" tree → `pinned` with folders and split views (split view with more than 3 tabs: keep the first 3, the others as single tabs); "unpinned" tree → today tabs (with `lastActive = Date.now()`); favorites → favorites (no duplicate URLs). Tab title: `title`, else `savedTitle`, else the URL. Safeguards: identifiers already seen (no cycle), depth 8, missing field = item ignored, never an uncaught exception.
- If the state only holds one empty space (no pinned tab, today tab, bookmark or group), replace it with the imported spaces.

**Chrome, Chromium, Brave, Edge**: JSON file `Bookmarks` in the `Default` profile. Mac: `~/Library/Application Support/` + `Google/Chrome`, `BraveSoftware/Brave-Browser`, `Microsoft Edge`. Linux: `~/.config/` (or `$XDG_CONFIG_HOME`) + `google-chrome`, `chromium`, `BraveSoftware/Brave-Browser`, `microsoft-edge`, then the Flatpak (`~/.var/app/<id>/config/…`) and Snap (`~/snap/chromium/common/chromium`) versions. Windows: `%LOCALAPPDATA%\` + `Google\Chrome`, `BraveSoftware\Brave-Browser`, `Microsoft\Edge`, then `User Data\Default`. Chromium is only offered on Linux. `roots.bookmark_bar`, `roots.other`, `roots.synced`; nodes `{ type: 'url' | 'folder', name, url, children }`. Result: bookmarks in the active space (bookmarks bar): the content of the bookmarks bar and an "Other Bookmarks" subfolder if it is not empty (and "Synced Bookmarks" likewise), directly in the bar if it was empty, otherwise in a "Chrome" (or "Brave", "Edge") folder at the end of the bar.

**Chromium profile** (Chrome, Chromium, Brave, Edge; Arc: `User Data/Default` next to `StorableSidebar.json`): the browser's `Default` folder. The SQLite databases are copied to a temporary folder before reading (the open browser locks them), `-wal` journal included, and read with `node:sqlite` as big integers (dates are in microseconds since January 1, 1601).

- History: `History`, table `urls` (`url`, `title`, `visit_count`, `last_visit_time`), without `hidden`, http(s) only, the 5,000 most recent. Merge: a known page adds up the visits and keeps the most recent one; only the 5,000 most recent pages are kept in total.
- Extensions: folders `Extensions/<id>` (32 letters a-p), except those marked `was_installed_by_default`, `from_webstore: false` or disabled (`state: 0`, or non-empty `disable_reasons`) in `extensions.settings` of `Secure Preferences` / `Preferences`: Signet does not keep an extension that is installed but disabled. Installed one by one from the Chrome Web Store (those already present are skipped), never pinned.
- Passwords: `Login Data`, table `logins` (`origin_url`, `signon_realm`, `username_value`, `password_value`, `date_created`), without `blacklisted_by_user` or app credentials (`android://`). Added to Signet's keychain; a credential already present (same site, same name) is kept as is. Decryption depends on the prefix of `password_value`:
  - Mac `v10`: AES-128-CBC, IV of 16 spaces, key PBKDF2-SHA1(secret, `saltysalt`, 1003 iterations, 16 bytes); secret read from the Keychain with `security find-generic-password -w -s "<Browser> Safe Storage"` (macOS asks for permission). Services: `Chrome`, `Chromium`, `Brave`, `Microsoft Edge`, `Arc` + "Safe Storage" (Arc's not verified).
  - Linux `v10`: same AES, key PBKDF2-SHA1(`peanuts`, `saltysalt`, 1 iteration); `v11`: secret from the GNOME keyring with `secret-tool lookup application <app>` (`chrome`, `chromium`, `brave`, `microsoft-edge`), 1 iteration. KWallet not supported.
  - Windows `v10`: AES-256-GCM (12-byte nonce after the prefix, tag in the last 16), key `os_crypt.encrypted_key` from `User Data/Local State` (base64, `DPAPI` prefix) decrypted by PowerShell (`ProtectedData.Unprotect`, current user). `v20` ("app-bound", recent Chrome): unreadable outside the browser, counted as a failure with the advice to export a CSV.

**Safari** (Mac only): `~/Library/Safari/Bookmarks.plist`, converted with `execFile('plutil', ['-convert', 'json', '-o', '-', path])`. Nodes: `WebBookmarkType` = `WebBookmarkTypeList` (`Title`, `Children`) or `WebBookmarkTypeLeaf` (`URLString`, `URIDictionary.title`); ignore `com.apple.ReadingList` and `History`. Result: bookmarks, as for Chrome (in a "Safari" folder if the bar was not empty), with `BookmarksBar` at the root and `BookmarksMenu` in a "Bookmarks Menu" subfolder. Permission error (macOS protects this folder) → dialog that explains how to grant Signet Full Disk Access (System Settings › Privacy & Security › Full Disk Access; in development, it is the "Electron" app), with a button that opens `x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`.
